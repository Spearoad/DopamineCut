# 카카오톡 숏폼 인식·집계 검증

개선 작업 지시의 기준에 따라 **진입 탐지 → 영상 식별 → 유형 분류 → 시간·횟수 집계**를 이어서 검증한 기록입니다. 코드 검증(단위 테스트)과 실기기 검증을 나눠 적고, 실기기에서 확인하지 못한 항목은 **미검증**으로 표기합니다.

## 1. 결과 요약

| 상황 | 정상 동작 기준 | 코드 검증 | 실기기 |
| :--- | :--- | :---: | :---: |
| 같은 영상 유지 | 일반 숏폼 1개 20초 시청 → 영상 수 1회, 식별자·세션 유지, 시간 증가 | 통과 | 미검증 |
| 다른 영상 전환 | 서로 다른 일반 숏폼 n개 각 10초 이상 → n회, 영상별 세션 구분 | 통과 (n=3) | 미검증 |
| 댓글·공유창 복귀 | 창을 10초 이상 열었다 복귀 → CV·OCR·시간 정지, 기존 내용 보존, 복귀 후 재개 | 통과 | 미검증 |
| 광고·기타 콘텐츠 | 광고는 숏폼 시간·횟수 제외 | 통과 | 미검증 |
| 라이브·사진 게시물 | 시간만 반영 | 해당 없음 | 해당 없음 |

> **실기기 미검증 사유:** 안드로이드 실기기를 보유하고 있지 않아 실기기 테스트를 진행하지 못했습니다. 지시서 기준에 따라 실기기 항목은 모두 **미검증**으로 표기하며, 안드로이드 폰이 있는 팀원이 3절의 절차와 기록표로 확인하면 결과를 반영합니다.

카카오톡 숏폼에는 라이브·사진 게시물 유형이 없어 해당 없음으로 둡니다. 숏폼이 아닌 화면(지금 탭 오픈채팅 피드, 친구·채팅 목록)은 광고와 같이 숏폼 시간·횟수에서 제외합니다.

## 2. 코드 검증

`app/src/test/.../logic/shortform/KakaotalkRecognitionScenarioTest.kt`

A 추적(`KakaotalkManager`), 파이프라인(`KakaotalkRecognitionPipeline`), 세션 반영(`KakaotalkSessionBinder`), 집계(`ShortformSessionTracker`)는 앱 코드를 그대로 쓰고, 화면 캡처와 ONNX 추론 결과만 테스트에서 정해 줍니다. 화면은 150ms 간격(앱의 화면 갱신 주기)으로 관측합니다.

| 테스트 | 확인 내용 |
| :--- | :--- |
| 같은 영상 20초 | 영상 수 1회, 세션 ID 1개 유지, 모델 판정 1번, 시청 시간 19~20초 |
| 서로 다른 영상 3개 각 10초 | 영상 수 3회, 세션 3개(ID·식별자 모두 다름), 각 9초 이상 |
| 댓글창 10초 → 복귀 → 공유창 10초 → 복귀 | 창이 열린 동안 모델 요청 0건, 세션 ID 유지, 복귀 후 재판정 없음, 누적 OCR 유지, 창이 열린 20초는 시간에서 제외, 영상 수 1회 |
| 판정 전 댓글창 열기 | 진행 중이던 모델 요청 취소, 창이 열린 동안 새 요청 없음, 취소된 요청의 늦은 결과 무시, 복귀 후 다시 판정 |
| 광고·비숏폼 | 모델 광고 판정, 지금 탭 기타 판정, 화면의 "광고" 표시 모두 영상 수 0, 숏폼 시간 0 |
| 이전 영상의 늦은 결과 | 이전 영상의 모델 결과(광고)가 다음 영상에 적용되지 않음 |
| 최근 3개 중복 방지 | A → B → A 시청 시 영상 수 2회, 세 번째 세션 시간은 유지 |
| OCR 보존 규칙 | 같은 영상의 창 열기·닫기는 OCR 유지, 다른 영상·이탈은 OCR 폐기 |

### 이번 개선에서 고친 점
- **댓글·공유창에서 누적 OCR이 지워지던 문제**: 화면 상태가 바뀔 때마다 OCR 캐시를 지우던 것을, 같은 영상에서는 보존하고 다른 영상으로 바뀌거나 숏폼을 벗어날 때만 지우도록 바꿨습니다(유튜브와 같은 기준). 진행 중인 캡처·OCR 작업은 창이 열릴 때 계속 취소합니다.
- **연결 구조**: `AppBlockService`에 있던 "파이프라인 결과 → 시청 세션" 반영을 `KakaotalkSessionBinder`로 분리해 전체 흐름을 단위 테스트로 확인할 수 있게 했습니다. 동작은 그대로입니다.

## 3. 실기기 검증 절차

카카오톡이 설치된 **안드로이드 폰**과 디버그 빌드가 필요합니다. 현재 안드로이드 실기기 미보유로 이 절차는 아직 진행하지 못했습니다. 테스트 전후 누적값의 차이로 판정합니다.

### 준비
1. 디버그 빌드를 설치하고 접근성 서비스를 켭니다.
2. 진단 로그를 켭니다(디버그 빌드에서만 동작, 화면 텍스트는 기본 제외).
   ```bash
   adb shell run-as com.example.dopaminecut2 touch cache/kakaotalk-diagnostics.enabled
   ```
3. Logcat 필터: `tag:KakaoTrackingDiagnostic | tag:AppBlockService | tag:KakaoUiDiagnostic`
4. 앱 통계에서 카카오톡 **숏폼 시간·영상 수**를 기록합니다(테스트 전 값).

### 확인할 로그
| 로그 | 의미 |
| :--- | :--- |
| `KakaoTrackingDiagnostic reason=... kind=... paused=... key=...` | A 추적 상태와 B 판정 반영 결과. 같은 영상이면 `key`가 유지되어야 함 |
| `KakaoTrackingDiagnostic CHECKPOINT session=... durationSec=... count=...` | 세션별 누적 시간·횟수. 같은 영상이면 `session`이 유지되어야 함 |
| `AppBlockService KakaoTalk 콘텐츠 판정: uiClass=... conf=... latencyMs=...` | 모델 판정 결과와 추론 시간 |
| `KakaoUiDiagnostic BEGIN ... state=... evidence=...` | 화면의 접근성 구조. 댓글·공유창을 열었을 때 `state=OVERLAY`인지 확인 |

### 기록표

| 상황 | 방법 | 테스트 전 (시간 / 수) | 테스트 후 (시간 / 수) | 로그 확인 | 결과 |
| :--- | :--- | :---: | :---: | :--- | :---: |
| 같은 영상 유지 | 일반 숏폼 1개를 20초 시청 | | | session·key 유지 | 미검증 |
| 다른 영상 전환 | 최근 본 적 없는 일반 숏폼 3개를 각 10초 이상 시청 | | | session 3개 | 미검증 |
| 댓글창 복귀 | 집계된 영상에서 댓글창을 10초 이상 열었다 닫기 | | | 창이 열린 동안 `paused=true`, 같은 session | 미검증 |
| 공유창 복귀 | 집계된 영상에서 공유창을 10초 이상 열었다 닫기 | | | 창이 열린 동안 `paused=true`, 같은 session | 미검증 |

| 지금 탭 기타·채팅 | 오픈채팅 피드·채팅 목록에 머물기 | | | 집계 없음 | 미검증 |

## 4. 실기기 로그 분석 (2026-11-21, SM-S916N · Android 16)

숏폼 시청 → 댓글창 → 공유창 → 복귀 순서로 받은 `KakaoUiDiagnostic`·`KakaoTrackingDiagnostic` 로그입니다. 수정 전 코드(현재 `main`)로 기록했습니다.

| 항목 | 로그에서 확인한 내용 | 판단 |
| :--- | :--- | :--- |
| 같은 영상 유지 | 한 세션에서 `CHECKPOINT durationSec=5 → 9 → 12 → 13`, `count=1` 유지 | 정상 |
| B 모델 판정 | 일반 숏폼 `SHORTFORM_NORMAL conf=1.000`, 추론 101~195ms | 정상 |
| 최근 3개 중복 방지 | 같은 영상으로 돌아온 새 세션이 `count=0` | 정상 |
| 댓글창 | 창 트리에 `design_bottom_sheet`·`touch_outside`가 생기고 플레이어 ID(`ktv_*`)는 사라짐. 하지만 "숏폼"·"좋아요" 글자가 함께 보여 `INSIDE`로 판정 → 새 영상으로 처리되고, 창이 열린 화면을 모델이 `SHORTFORM_AD`(0.919)로 판정 | **비정상 → 수정** |
| 공유창 | 같은 `design_bottom_sheet` 구조. 채팅방 목록이 보이며 `EXPLICIT_AD`로 세션 종료(채널 메시지 미리보기 "(광고)" 글자로 추정, 로그는 글자 내용 미기록) | **비정상 → 수정** |
| 공유창 종류 | 카카오톡 내부 시트(채팅방 목록·검색·하단 메뉴). 안드로이드 시스템 공유창이 아님 | 확인 |

### 수정 내용 (`KakaotalkTracking.kt`)
- 댓글·공유창 판별 ID에 실기기에서 확인한 `design_bottom_sheet`를 추가했습니다. 일반 시청·채팅 목록 화면 로그에는 이 ID가 없습니다.
- 시청 중인 영상 위에 창이 열린 경우에는 광고 글자 검사보다 창 판별을 먼저 해서, 창 안의 "(광고)"·댓글 글자 때문에 세션이 끝나지 않게 했습니다. 시청 중인 영상이 없을 때의 광고 제외는 그대로입니다.
- 로그 구조를 그대로 옮긴 `KakaotalkOverlayDetectionTest`(5개)를 추가하고, 시나리오 테스트의 댓글·공유창도 실기기 구조로 바꿨습니다. 수정 전 코드로 돌리면 4개가 실패해 실기기에서 본 문제를 재현합니다.
- 수정 후 실기기 재확인은 아직이라, 1절의 실기기 칸은 재테스트 후 갱신합니다.

## 5. 남은 위험과 확인 필요 사항
- **수정 후 실기기 재확인**: 댓글·공유창에서 `reason=PLAYER_OVERLAY paused=true`가 나오고, 닫은 뒤 같은 `session`으로 이어지는지 다시 확인해야 합니다.
- **채팅 목록 오판 가능성**: 채팅 목록 화면도 대화 미리보기에 "숏폼"·"좋아요"가 있으면 `INSIDE`로 잡힐 수 있습니다(로그에서 확인). 이 경우 B 모델이 `CHAT_FRIENDS`로 판정해 집계에서 빠지지만, A 판별에 플레이어 ID(`ktv_player_container` 등)를 근거로 추가하면 더 안전합니다.
- **학습 화면**: 모델은 iPhone 캡처로 학습했습니다. 실기기 로그에서 일반 숏폼은 높은 신뢰도로 맞혔지만, 광고 실화면 판정은 아직 확인하지 못했습니다.
